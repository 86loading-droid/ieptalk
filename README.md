# IEP톡

현장 특수교사가 IEP 작성·진전도 점검·행동 기록을 한곳에서 하고, 교사끼리 메신저와 회의·전화 예약으로 협업하는 웹앱(시연판)입니다.

- 시연 주소: https://86loading-droid.github.io/ieptalk/
- 로그인 없이 둘러보기(가상 자료, 브라우저 안에서만 동작): https://86loading-droid.github.io/ieptalk/?demo=1
- 시연판에는 가명·가상 학생만 넣습니다. 실제 학생 정보는 학교 서버로 옮긴 뒤 학교의 심의를 거쳐 사용합니다.

## 누가 무엇을 하나

| 역할 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 관리자(교사) | 교사가 하는 모든 일, 구글 계정 초대·역할 지정, 학사일정·경고 기준 설정 | |
| 교사 | 학생·IEP 목표·진전도, 표적행동 정의와 기초선, 행동 기록, 메신저, 회의·전화 예약, 공유 메모, 할 일 | |
| 보조인력 | 배정된 학생의 행동 즉시 기록(휴대폰), 자기가 저장한 기록 보기·수정·삭제 | 메신저, 일정, IEP 목표, 다른 사람이 남긴 기록 보기 |

보호자 채널은 이번 시연판에 넣지 않았습니다.

## 주요 기능

1. 한눈에 보기(첫 화면): 모든 기능을 패들릿 담벼락처럼 펼쳐 보여 주고, 칸 제목을 누르면 세부 화면으로 들어갑니다. IEP 법정 기한(팀 구성 2주, 계획 작성 30일, 학기 평가), 진전도 경고, 7일 안 일정, 응답할 초대, 할 일, 안 읽은 대화.
2. 학생·IEP: 조건·행동·기준 3요소 점검, 측정값 입력, 목표선 그래프, 최근 N회 연속 목표선 아래면 경고(기본 3회)와 「팀 회의 예약」.
3. 행동·기초선: 표적행동의 조작적 정의(해당·비해당 예), 빈도(한 번 누름)·지속시간(시작·끝) 즉시 기록 버튼, 「관찰했고 발생 없음」, 날짜별 그래프(세로축은 「하루(관찰 회기 합계)」: 하루 안의 관찰 회기를 합친 값), 평균·중앙값·범위·추세, 안정성 참고값, 선행사건·결과 집계(기능 가설 도움), 기초선 확정 후 중재(B) 단계 표시.
4. 메신저(교사 전용): 1:1·모둠·학생 IEP팀 대화, @이름 부르기, 읽음 표시, 메시지를 할 일로, 근무시간 외 「아침에 보내기」.
5. 알림 띠: 메신저에서 전화 예약, 긴급회의 공지, 일반 공지를 한 사람 또는 여러 사람에게 보내면 받는 사람 화면 맨 위에 깜박이며 뜹니다. 「확인」으로 깜박임을 끄고 「삭제」로 띠에서 지울 수 있으며, 메신저 대화방의 기록은 그대로 남습니다. 회의·전화 예약을 보내도 같은 알림이 뜹니다.
6. 일정·예약: 회의 예약, 전화 예약(받는 사람과 선택 내용만), 교사 공유 달력, 국가 공휴일(관공서 공휴일·대체·임시공휴일, js/holidays.js), 학사일정(관리자 입력, 여러 날 가능), 선생님들 간의 개인 약속(함께하는 사람만 보임), 보기 고르기(공휴일·학사·회의·약속), 참석자 수락·거절, 겹치는 일정 경고, 모두 비어 있는 시간 추천, 구글 캘린더에 추가, 대화방에 예약 카드 자동 전송.
   - 학사일정 파일로 넣기(관리자): 엑셀(xlsx·xls·csv), 한글(hwp·hwpx), PDF, 붙여 넣은 글에서 날짜·일정 이름을 찾아 미리보기 → 고친 뒤 고른 것만 넣기. 양식 엑셀 내려받기, 달력 모양 엑셀 인식, 공휴일·이미 있는 일정·학년도 밖 일정은 자동으로 빼 둠. 파일은 브라우저 안에서만 읽음(js/importer.js, 라이브러리는 js/vendor/LICENSES.md). 배포용·암호 한글은 미리보기 글만, 스캔 PDF는 읽지 못함.
7. 공유 메모: 소제목·문단·체크리스트 블록, 동시 편집, 회의 안건·행동 관찰 양식.
8. 위기행동 사후 기록(교사만): 사건 기록 → 학교장 보고·보호자 통지 → 팀 회고 → 마무리 4단계. 행동 기록에서 「물리적 제지 있었음」을 체크하면 사후 기록 요청이 뜹니다. 팀 회고 기한은 법정 수치가 없어 학교 설정값(기본 2 수업일, 주말·공휴일 제외)으로만 안내합니다. 그래프에 사건 날을 ★로 표시하고, 정한 기간 안 사후 기록이 기준 건수 이상이면 행동지원계획 재검토를 제안합니다. 근거: 「교원의 학생생활지도에 관한 고시」(교육부고시 제2023-28호).
9. 평가조정 한 장(교사만): 교과별로 제시·반응·시간·장소·일정 조정을 정리하고 통합학급·교과 교사에게 확인을 요청합니다. 성취기준을 바꾸는 교육과정 수정은 따로 경고하고, 내용이 바뀌면 다시 확인을 받습니다. 효과 메모, A4 한 장 인쇄.
10. 측정 방법: 빈도, 지속시간에 더해 간격기록(부분간격·전체간격·순간표집, 간격마다 진동·소리·화면 신호)과 잠재시간(지시 → 행동 시작).
11. 관찰자 간 일치도: 「두 번째 관찰자로 기록」을 켜고 남긴 기록은 그래프에서 빼고 일치도 계산에만 씁니다(빈도·지속시간 총합 일치도, 간격기록 간격별 일치도). WWC 단일대상설계 기준(평균 80% 이상, 단계마다 회기의 20% 이상)과 비교해 보여 줍니다.
12. 접근 기록(관리자만 열람): 학생 자료의 열람·작성·수정·삭제·인쇄를 자동으로 남기며, 누구도 고치거나 지울 수 없습니다.
13. 연결 끊김 대비: 기록은 기기에 먼저 저장되고 연결되면 올라갑니다. 서비스 워커(sw.js)가 앱 화면 파일을 보관합니다. 연결이 끊기면 화면 위에 안내 띠가 뜹니다.
14. 첫 로그인 안내: 역할별 3~4장, 위쪽 「도움말(?)」로 다시 보기.
15. 첫 화면 「내 책상」 위젯: 시계, 지금 이 시간(현재 교시·남은 시간·다음 시간), D-Day(학사일정 ☆ 별표), 이달 달력, 할 일, 메모(나만 보는 메모, 입력 즉시 저장), 주간 시간표(교시 시간·과목 편집, 지금 칸 강조), 학사일정. 시간표·메모·별표는 본인만 읽고 씁니다(desks/{uid}).
16. 날씨·급식 위젯과 교사 컴퓨터용 좌우 배열(v14): 지금 날씨(Open-Meteo 예보, 미세먼지 모델 추정), 급식(NEIS 급식식단정보, 날짜 넘기기·조식/중식/석식). 급식 학교와 날씨 지역은 관리 화면에서 정하며 기본값은 포항명도학교·포항 북구입니다. 넓은 화면(1280px 이상)에서는 왼쪽에 내 책상, 오른쪽에 학생 지원·협업을 따로 스크롤되게 나란히 놓고, 위젯 칸 수는 차지한 폭에 맞춰 바뀝니다(화면 배율 125%·150% 대응).
17. 알림 상황판(v15): 긴급회의·전화 예약·공지 알림은 한눈에 보기 맨 위에 「확인」할 때까지 깜박이며, 확인 뒤에도 「삭제」 전까지 남습니다(다른 화면에서는 화면 맨 위 띠). 보내기 창의 「나에게도 보내기」로 내 화면에도 띄울 수 있고, 나에게만 보내면 대화방 없이 알림만 남습니다.
18. 한눈에 보기 배치 편집(v16): 「화면 편집」을 누르면 칸마다 순서(◀ ▶ ▲ ▼, 끌어서 옮기기), 너비(좁게·보통·넓게·아주 넓게·한 줄 전체), 높이(자동·낮게·높게), 이름 바꾸기, 숨기기를 할 수 있고, 숨긴 칸은 다시 넣거나 「기본 배치로」 되돌릴 수 있습니다. 배치는 교사마다 따로 저장됩니다(desks/{uid}.layout).
19. 신체적 개입 사후 보고서(v17): 위기행동 사후 기록에서 「보고서」를 누르면 버튼으로 사실을 골라(배경사건·선행 자극·행동 유형·위험 수준·개입 이유·먼저 해 본 조치·개입 방법·접촉 부위·자세·놓은 근거·부상·보고·통지·회복 대화) 문장·문단 보고서가 바로 만들어지고 「보고서 복사」로 한글·워드에 붙여 넣을 수 있습니다. 버튼 이름과 문장은 교사마다 고칠 수 있습니다(desks/{uid}.pirChips). 관찰·판단·전해 들은 것을 문장에서 나누고, 빈칸은 [적지 않음]으로 드러내며, 금지 행위(목·흉부 압박, 엎드린 자세 등)는 확인 표시한 것만 「없었음」으로 씁니다. 「확정」하면 본문 SHA-256 확인값·작성자·시각이 남고 확정 뒤 고친 것은 정정 이력으로 쌓입니다. 바탕: 최현석 「NICB 체계 물리적 개입(신체적 블로킹) 서면 보고서」 양식(2026), 퀸 「사후보고서 서식 일곱 칸」 초안.
20. 버튼별 상세 예시(v18): 신체적 개입 보고서에서 버튼을 고르면 그 버튼 아래에 상세 예시 드롭다운(버튼마다 5~7개, 모두 94개 버튼)과 상세 칸이 나타납니다. 예시를 고르면 상세 칸에 들어가고, 사실대로 고쳐 쓰면 보고서 문장 끝 괄호에 들어갑니다(접촉 부위·자세는 고른 표현으로 바뀜). 예시는 「버튼 고치기」에서 줄마다 하나씩 고칠 수 있습니다(js/views/pirexamples.js).

점검 도구: tools/smoke.py(기존 화면), tools/feature-test.py(v13 새 기능 40항목), tools/rls-test.mjs(학교 DB 권한).

## 처음 쓰는 방법(시연)

1. 관리자(86loading@gmail.com 또는 hschoi@uu.ac.kr)로 로그인합니다.
2. 관리 → 구글 계정 초대에서 이메일, 이름, 역할(교사·보조인력), 직책을 넣습니다. 10명 정도 초대할 수 있습니다.
3. 관리 → 「가상 학생 예시 넣기」를 누르면 가상 학생 3명, 목표, 표적행동, 기초선 기록이 들어갑니다.
4. 초대받은 사람에게 시연 주소를 알려 줍니다. 처음 구글 로그인을 하면 초대한 역할로 들어옵니다.
5. 보조인력은 휴대폰에서 주소를 열고 「홈 화면에 추가」를 하면 앱처럼 쓸 수 있습니다.

js/views/*.js         화면별 코드(오늘, 학생, 행동, 메신저, 일정, 관리, 보조인력)

## 학교 DB 이식

화면 코드는 `js/store.js`의 공통 함수(`sub`, `create`, `update`, `remove`, `saveSchool`, `init`, `signIn`, `signOut`)만 씁니다. 학교 서버로 옮길 때는 다음 순서로 합니다.

1. `db/schema.sql`을 학교 PostgreSQL에 실행합니다. 역할별 권한은 행 단위 보안(RLS)으로 DB가 강제합니다.
2. 학교 서버의 API(또는 Supabase)를 붙이는 저장소 파일을 `js/store.js`와 같은 함수 모양으로 만듭니다. 로그인한 사용자 식별값은 요청마다 `SET LOCAL app.user_id = '<uid>'`로 넘깁니다.
3. `js/config.js`의 `SCHOOL_ID`, 관리자 이메일, 서버 주소를 학교 값으로 바꿉니다.
4. `node tools/rls-test.mjs`로 권한(보조인력은 자기 기록만 등)이 지켜지는지 확인합니다.
